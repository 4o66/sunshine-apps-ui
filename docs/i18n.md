# Translating this

Two jobs, and most languages only need the first.

| | where | who can do it |
|---|---|---|
| **Strings** — the interface | `locales/<code>.json` | anyone who speaks the language |
| **Tile artwork** — words baked into pictures | `assets/tiles/<code>/` | only for scripts we can render; see below |

## 1. The strings

Copy `locales/en.json` to `locales/<code>.json` — a BCP 47 tag: `fr`, `de`,
`pt-BR`, `zh-Hans` — and translate the values, never the keys. Fill in
`_meta`. Send a pull request.

The whole English catalogue is under 4 KB, which is why strings ship with the
program rather than being downloaded. **A partial translation is useful from
the first line**: anything you leave out falls back to English, and nothing is
ever blank.

`{count}` and `{seconds}` are substituted at runtime. Keep them; put them
wherever your language needs them.

Two things not to translate:

- **Keys.** `ui.rescan` is an address, not a word.
- **The `#1` and `Zz` prefixes** in the `names` section. They are sort keys —
  both Sunshine's list and Moonlight's grid order applications alphabetically
  and neither lets you arrange them by hand — so `#1 Desktop` leads the grid
  and `Zz Steam` stays out of the middle of somebody's games. Translate the
  words after the prefix, keep the prefix.

## 2. The artwork

A tile is a 600×800 picture with the caption drawn into it. **Every language
is welcome to have a set.** The constraint is not on the language — it is on
what *we* can generate automatically.

`scripts/make-tiles.py` draws the captions with the Pillow we ship, which has
**no text shaping** — no raqm, no harfbuzz, no fribidi. That is a limit of our
generator, not of the script. Measured:

| script | can our generator draw it? |
|---|---|
| Latin, Cyrillic, Greek | yes |
| CJK — Japanese, Korean, Chinese | yes, given a font (no shaping needed) |
| **Arabic** | no — letters come out unjoined and in left-to-right order |
| **Hebrew** | no — reversed |
| **Devanagari, Thai** | no — marks in the wrong places |

A "no" means *we* cannot produce that set from a string; it does not mean the
set should not exist. A person using a tool that shapes the script properly
can letter the templates and send the finished pictures, and that contribution
is as welcome as any other — more so, because it is the only way those
languages get worded tiles.

So there are three paths.

### If your script is in the "yes" rows

Put a `tiles` section in your catalogue and build the set:

```bash
python3 scripts/make-tiles.py --lang fr
```

That writes `assets/tiles/fr/`. **Look at every tile before committing it** —
especially that a long name has not shrunk to something unreadable. The fitting
rule drops the size until the caption fits, so a very long translation gets
small rather than clipped.

### If your script is in the "no" rows

You have two options, and both are fine.

**Stop at the strings.** The interface will be in your language and the tiles
will be wordless. Nothing is broken; wordless artwork is correct everywhere.

**Or letter them by hand** — see below. This is the only route to worded tiles
in your language, and it is a genuinely valuable contribution rather than a
workaround.

### Lettering by hand

`assets/tiles/_template/` holds the canvases: every tile with its mark in
place and the caption area empty. Add the text in whatever tool shapes your
script properly — a real design tool will do it correctly where our generator
cannot — keep to the layout below, and send the finished PNGs as
`assets/tiles/<code>/`. This route is open to any language, including ones we
*could* generate, if you would rather set the type yourself.

`assets/tiles/_template/_layout-guide.png` is the same rules drawn on top of a
real tile.

## Artwork layout

Full specification, including how the background is generated and where every
mark came from: **`docs/tile-art.md`**. The short version for hand-lettering:

| | |
|---|---|
| Canvas | 600 × 800, PNG, opaque — do not resize |
| Margins | 48 px each side; **no ink may cross them** |
| Mark | already placed in the 420 × 330 box at the top; do not move it |
| Caption | Arial Bold or an equivalent grotesque, UPPER CASE, white |
| Size | 66 px maximum; reduce until it fits, do not clip |
| Position | centred on x = 300; top at y = 630 for one line, y = 600 for two, second line 14 px below the first |
| Letter-spacing | one space between characters where it fits; drop it before dropping below a readable size |

Two lines are normal for a long name: `SUNSHINE` above `APP MANAGER`. Split
after the first word.

## What the program does with all this

`i18n.py` reads the machine's language, walks the fallback chain (`pt-BR` →
`pt` → `en` for strings) and lays the catalogue over English. For artwork the
chain is `pt-BR` → `pt` → wordless — **English is deliberately not a fallback
for pictures**, because a French machine showing English tiles would be
confidently wrong, and wordless is merely quiet.

Artwork falls back tile by tile, so a set that covers the common four and not
every distribution logo still works; the rest come from the wordless set.

## Choosing a language in the program

Settings has a **Language** selector. It lists "Follow the system" and every
catalogue in `locales/`, named in itself with its English name beside it, and
it sets one preference: `language`, read by `i18n.chosen()`.

Two things about where that preference is read. It is read from the same
preferences file the web interface writes, but it is read by `i18n`, which the
*engine* uses — so a scan from the command line writes the same tiles as the
button that runs a scan. And `SAU_LANGUAGE` in the environment still wins over
it, which is how you test a language without changing the setting.

**The selector governs the tiles, not the interface.** Every interface string
is in `locales/en.json` and ready to be translated, but `render.py` still
writes English directly; wiring the interface through `i18n.text()` is a
separate job. The setting says so rather than implying more than it does.

## Artwork that is not in the box

A set of tiles is a couple of megabytes per language, so the program ships
English and the wordless set — one of which is always right — and fetches any
other language when somebody asks for it.

`assets/tiles/manifest.json` is the index: every shipped set, every file, and a
sha256 for each. `scripts/make-tiles.py` rewrites it whenever it writes tiles,
so it cannot fall behind the artwork; `--manifest-only` rebuilds just the index.

| what | where |
|---|---|
| the index | `assets/tiles/manifest.json`, published at `raw.githubusercontent.com/4o66/sunshine-apps-ui/main/assets/tiles/` |
| the code | `tileart.py` |
| the buttons | Settings → Language |

**What the hashes do and do not prove.** Every downloaded file is checked
against the manifest, which catches a truncated file, a proxy that rewrote
something, or a half-finished publish. It is not a signature: the manifest
comes from the same place as the files, so it proves the download matches what
that server said, not who the server is. HTTPS and a fixed host stand behind
that.

Three rules the code keeps, each with a test:

- **A manifest is data, not instruction.** Only `*.png`, only bare filenames,
  only plausible language codes; anything with a slash, a suffix we do not
  serve, or a hash that is not a hash is dropped before it is acted on.
- **A set arrives whole or not at all.** Every file is downloaded and verified
  before any of it is written. A half-finished set would leave a grid half in
  one language and half wordless, which reads as a bug in the program rather
  than as an interrupted download.
- **Only sets you already have are checked for updates.** "Check for new tile
  artwork" compares the wordless set and any language you asked for. It never
  offers to download the other forty, which is how an update check turns into
  a hundred megabytes.

Changing the language downloads nothing by itself. If a set is published for
the language you pick and it is not here, the page says so and offers a button.
After a download the tiles are on disk but not yet on the grid: the next scan
stages the change like any other, so you see it before anything is written.
